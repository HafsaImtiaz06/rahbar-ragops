# Kubernetes manifests: bring-up, Jobs, release

Namespace `rahbar`. Everything is applied through kustomize on top of `k8s/base`. Overlays: `dev` = images built locally for minikube (this is the one you use), `ci` = kind cluster with fixture documents and a fake model, `prod` = images from Docker Hub tagged by commit SHA.

| Path | What it is |
|---|---|
| `base/api.yaml`, `ui.yaml`, `redis.yaml` | API Deployment (3 replicas, `maxUnavailable: 0`, `/healthz` + `/readyz`, read-only root filesystem), UI, semantic cache |
| `base/chroma.yaml` | vector store StatefulSet with its own PVC |
| `base/corpus-pvc.yaml`, `ragops-state-pvc.yaml` | documents; data lake, quarantine and archived versions (survive pod restarts) |
| `base/indexer-job.yaml`, `reindex-cronjob.yaml` | ingestion with verification: the only writer to Chroma |
| `base/configmap.yaml`, `networkpolicies.yaml` | settings; default-deny policies with explicit allows |
| `base/traces-pvc.yaml`, `patch-api-traces.yaml`, `patch-api-service-track.yaml` | trace volume for the API, and the `track: live` / `track: candidate` label split |
| `eval-job.yaml` | Part B suite + release gate as a Job; thresholds in ConfigMap `rahbar-eval-thresholds` |
| `candidate/` | candidate Deployment / Service / Jobs, generated by `scripts/f3_release_demo.sh` |
| `tools/` | helper pods (corpus loader, shell with PVC access) |

## A fresh cluster to a working pipeline

```bash
OLLAMA_HOST=0.0.0.0 ollama serve &          # on the laptop; also: ollama pull llama3.2:3b && ollama pull nomic-embed-text
make cluster                                # minikube + Calico (NetworkPolicy needs it) + metrics-server + ingress
make host-ip                                # then see "Reaching Ollama" below
make install && make fetch                  # python tools; downloads corpus/sources.yaml (committed: do not replace it)
make images && make eval-image              # api, indexer, ui and eval images, loaded into minikube
make apply && make corpus-load              # manifests; copies corpus/raw to the corpus PVC; the indexer Job then runs
kubectl -n rahbar get jobs,pods -w          # wait: job/indexer Complete, api 3/3 Ready
kubectl get all,pvc,configmap,cronjob,job -n rahbar      # the F1 inventory
```

Ask: `make ask Q="What CGPA puts a student on academic warning?"` (Windows/macOS: `minikube tunnel` and use 127.0.0.1 for `rahbar.local`).

### Reaching Ollama (the one machine-specific setting)
The pods call Ollama on the laptop through `OLLAMA_URL` (`k8s/base/configmap.yaml`) and the `ipBlock` rules in
`k8s/base/networkpolicies.yaml` and `k8s/eval-job.yaml`. Both `192.168.65.254` (Docker Desktop) and `192.168.49.1`
(native Linux docker driver) are allowed. Check from inside the cluster, using the address you will put in `OLLAMA_URL`:
```bash
minikube ssh "curl -s http://192.168.65.254:11434/api/tags | head -c 100"
```
On WSL 2 + Docker Desktop `make host-ip` prints `192.168.49.1`, which Ubuntu does not own: use `192.168.65.254` in `OLLAMA_URL`
(keep that edit out of commits: `git update-index --skip-worktree k8s/base/configmap.yaml`).

## Jobs
```bash
make index                 # re-run ingestion now (= create a Job from the reindex CronJob); the CronJob runs it on a schedule
make eval-job              # Part B suite + gate as Job "eval"; exits non-zero when the gate fails; results on PVC eval-results
kubectl -n rahbar get job eval -o jsonpath='{.status.conditions[*].type}'      # Complete | Failed
```
Gate thresholds are a ConfigMap, so changing one changes the outcome with no image rebuild:
```bash
kubectl -n rahbar edit configmap rahbar-eval-thresholds     # change one threshold, save
make eval-job                                               # same image, different gate result
```

## Controlled release (Part C3 / F3)
`scripts/f3_release_demo.sh` (run from the repo root with the venv active). Candidate collections must **never** be named
`rahbar-*`: the live indexer deletes every `rahbar-*` collection that is not active or previous. The default base name is `cand`.
```bash
scripts/f3_release_demo.sh candidate-index    # candidate index (chunking 200:30) built by an indexer Job
scripts/f3_release_demo.sh candidate-up       # second Deployment + Service api-candidate (own collection)
scripts/f3_release_demo.sh eval-candidate     # the Part B suite Job against api-candidate; prints GATE: PASS or FAIL
scripts/f3_release_demo.sh release            # ONLY after PASS: rolling update of the live Deployment, maxUnavailable 0
scripts/f3_release_demo.sh bad-release        # a release that should not ship
scripts/f3_release_demo.sh undo               # kubectl rollout undo, then a new trace showing the previous collection
```
